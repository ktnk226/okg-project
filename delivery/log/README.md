# デリログ：売上シミュレーション

現行の日別計画・実績反映仕様の正本は[Driveの作業資料](https://docs.google.com/document/d/1UptceMRlkVnpmqqXgzuNIlddjVYu7xzDZX3DUkZE97M/edit)です。下記の旧方式の説明は変更履歴として参照してください。現行画面では計画方式・週合計件数の入力を廃止し、`daily-planning.js`で日別計画と明示的な実績反映を計算します。`simulation-outlook.js`は実績・残り計画・報酬見込みの着地合計と、日別編集時の配分残額を読み取り専用で算出します。旧計算関数と保存フィールドは互換性検証のため保持しています。

## 今日の実績の自動繰越（現行）

稼働画面で実績を入力すると、今日の不足・超過をその期間の翌日以降の稼働日へ自動で配分し直します。「売上管理に実績を反映」ボタンは廃止しました。今日の目標は変わりません。

例：3日間で30,000円、Uberクエスト90件で報酬9,000円なら、1日の配達目標は7,000円です。今日5,000円で終えると、不足2,000円を明日以降に上乗せし、残り2日は8,000円ずつになります。クエストの残り件数も同様に配分し直します。

- 稼働画面の目標カードに、翌日以降の日別目標（今の実績で今日を終えた場合）を表示します。
- 確定計画の金額・件数を固定するのは、今日確定し、その後に今日の実績が変わっていない場合だけです。前日以前に確定した計画、確定後に実績が変わった計画は、単価・UPHだけを保持して繰越を反映します。
- 着地合計では、実績を入力した今日は実績だけを数え、今日の未達分は翌日以降の計画として一度だけ数えます。

### 金額表示（目標・売上・あと）

稼働画面と売上管理の週タブでは、金額を「目標」「売上」「あと」の3種類に絞って表示します。期間の目標は報酬込み、日別の目標・売上は配達分（報酬を除く）です。期間カードには、未入力のクエスト報酬見込みを差し引いた「配達であと」を併記します。翌日以降の日別目標には、今日を目標どおり終えた場合からの差（今日の不足・超過分）を表示します。シミュレーション売上合計・試算の過不足・実績ベース／確定計画後の残りの表示は廃止しました。

現行コードの確認コマンド：

```sh
node delivery/log/planning.test.cjs
node delivery/log/daily-planning.test.cjs
node delivery/log/confirmation.test.cjs
node delivery/log/outlook.test.cjs
# ローカルHTTPサーバーの公開先を指定。Chromium/Playwrightが必要。
DELILOG_TEST_URL=http://127.0.0.1:8020/delivery/log/ node delivery/log/browser.test.cjs
DELILOG_TEST_URL=http://127.0.0.1:8020/delivery/log/ node delivery/log/input-uph.browser.cjs
```

`input-uph.browser.cjs`は、会社別計画件数の消去・再入力（逆方向・0件を含む）、空欄の保存・再読込とv16 JSON復元、各セットのUPHをPC/iPhone相当のChromiumで確認します。必要なら`CHROMIUM_PATH`でブラウザ実行ファイルを指定できます。

件数の片方を空欄にすると、その会社だけ自動計算へ戻り、もう片方の手入力（0件を含む）を保持します。両方の件数が指定されている間は件数×単価で目標を試算し、空欄がある間は直前の目標を基準に、Uber必須件数と「不足売上を補う会社」の既存ルールで自動計算します。手入力の会社へは自動追加しません。金額を明示して逆算する操作では両社を自動計算へ戻します。

稼働セットの時給の横に、同じセットの配達件数（全社の累計差分）÷時給と同じ稼働時間を小数第1位の`UPH 3.0件/h`形式で表示します。稼働時間が0または時刻未入力なら`UPH —`、時間が正で件数が0なら`UPH 0.0件/h`です。保存項目・キー・バックアップ形式の変更はありません。

日別条件・実績反映スナップショットに加え、編集中の条件（drafts）、確定計画（confirmed）、当日内の再配分基準（planAnchors）を既存のplanningキー内に保存し、読み込み時に検証します。完全バックアップは既存v16形式を継続します。 前半不足の繰越額は設定目標へ保存せず、金曜以降に同じ週の保存済み実績から算出します。日別配達目標とUber必須件数を確保して、その日の不足分だけを選択会社の件数へ切り上げ換算します。計算は`daily-planning.test.cjs`、実績修正・日跨ぎ・JSON往復の画面操作は`browser.test.cjs`で検証します。

「目標管理」「逆算」を「🧮 売上シミュレーション」に統合。週・月・年の3タブで目標を設定します。ホームの日・週・月・年の集計切り替えと、日々の実績入力は継続します。

## 週とホーム

- 週は月〜日、日本時間04:00を営業日の境界とします。
- 週目標から入力済み実績を差し引き、過去の日と休みを除いた稼働日に配分します。
- 日別の指定額はその日の総額です。指定額と実績の高い方を確保し、残りを自動配分日に均等配分します。1円単位の余りは日付順に配分します。
- 例：残り3日・30,000円なら10,000円ずつ。今日を8,000円に指定すると、残りは11,000円ずつ。
- 当日実績が自動配分額に達するまでは当日の目標総額を維持し、残り必要額・件数・時間が減少します。超過分はほかの日の必要額を減らします。
- 配分する日がない不足額、指定額による過剰配分は明示します。
- ホームは今日の週配分を表示します。ホームから配分を直接編集せず、売上シミュレーションの週タブへ移動します。
- 必要件数は通常単価・会社比率による売上条件と、Uberクエストの本日ノルマを満たす件数です。必要時間は追加件数÷UPH。単価やUPHがない場合は未設定と表示します。

## Uber Eatsクエスト

- 前半は月〜木、後半は金〜日。Uber Eatsの入力済み件数だけを集計し、対象外件数を控除します。他社の件数は加算しません。
- 基本達成と追加10回の報酬を別に設定します。「達成を確認」しても実績売上を自動作成しません。
- 入力済みの確定報酬と、未入力の報酬見込みを分けて表示します。実績集計には、ホームに入力した売上・報酬だけを含めます。
- クエスト期間内に入力済みのUber報酬は見込みから自動控除します。別日に入力済みの報酬は明示的に紐付けます。各報酬は一度だけ控除し、入力済み金額を超える紐付けは保存しません。
- 同期間の別種のUber報酬も自動控除の対象になるため、見込みは保守的な値になります。実績売上はそのまま保持します。
- 未確認のまま終了したクエストは見込みから外れます。結果を確認した未入力報酬は、実績に入力するまで見込みとして区別します。
- 「クエスト見込みを週の必要売上から差し引く」は週ごとの任意設定で、初期状態はオフです。見込みが実績に混ざることはありません。

## 月・年

- 対象期間内に入力した全プラットフォームの通常売上・報酬を、日ごとの最終累計値から一度ずつ集計します。
- それぞれの目標・残り想定稼働日数・今後1日あたりの追加売上から、必要売上と着地を計算します。残り日数には今日を含みます。
- 今後1日の売上想定が空欄の場合は、対象期間内で今日までに売上を入力した日の平均を使います。今日の追加想定は、既に入力した売上に上乗せする金額です。
- 週・月・年の目標と想定は独立しています。月や年の変更で週目標・日別配分を上書きせず、週からも月・年を上書きしません。
- 月・年の計算にはクエストの未入力見込みを含めず、試算から実績への書き込みも行いません。

## データ互換性

既存の保存キーを継続します。

| データ | localStorageキー |
| --- | --- |
| 売上実績 | `delivery_log_vault_v13` |
| 期間別目標 | `delivery_log_periodic_goals_v13` |
| 稼働予定・クエスト・試算設定 | `delivery_log_planning_v15` |
| メモ | `delivery_log_inbox_memos_v13` |
| 経費 | `delivery_log_expenses_v1` |

既存の週・月・年の目標キー、件数目標、クエスト、日別指定、プリセットを保持します。以前の日目標は日別指定として読み込み、「自動配分」への明示的な切り替えで解除できます。廃止した比較画面の設定値も保存データから削除しません。

新しい `weekly`（週ごとの見込み反映）と `horizons`（月・年ごとの想定）は任意フィールドです。旧v15の計画は書き換えずに読み込めます。JSONバックアップはv16で出力し、v13・v14・v15・v16および従来の実績単体形式を読み込めます。旧バックアップにない計画・経費は現在の値を保持します。

計画データの読み込みに失敗した場合は、元の値を上書きせず保存を停止します。設定画面で有効なJSONバックアップから復元できます。

## クエスト優先方式と小数UPH

計算条件の「計画方式」で、従来の会社・固定比率方式と「Uberクエストを確保し、出前館で不足を補う」を切り替えます。新方式では週の目標から実績と未入力の報酬見込みを差し引き、クエスト期限内のUber残件数×設定単価を確保し、残額を出前館単価で割って切り上げます。Uberは売上目標に到達してもクエスト残件数を確保します。報酬見込みの控除は新方式では常に有効です。

両社の件数は過去の日と休みを除いて配分します。Uberの配分は各クエスト期限内に限定します。例の100件は34・34・32件、出前館15件は5件ずつです。日別金額・件数指定より会社別の計画を優先します。稼働日がない場合は未配分件数を表示します。

「当初の計画件数を維持する場合」の平均単価は、現在の目標・単価・休み設定から実績ゼロで組んだ件数計画のうち、今後の日に残る両社の件数（当日実績件数を控除）で、配達売上の不足額を割った値です。過去の未達売上を残りの計画件数で補うために必要な両社合計の平均単価で、報酬は含みません。履歴として固定保存した当初計画ではなく、現行条件による比較値です。

UPHはプリセット・計算条件とも0.1刻みで入力できます。値を丸めず保存し、必要時間＝件数÷UPHを分単位で切り上げます。保存キー・JSONバージョンは維持し、計算方式は省略可能な追加設定です。旧データは従来方式として読み込みます。


## 会社別件数の直接入力

比率入力は廃止し、計算条件でUber Eats・出前館それぞれの週合計件数を入力します。件数を重みとして扱わず、実績件数を控除した残件数を残り稼働日に配分します。Uberはクエスト残件数を最低限確保します。入力件数×設定単価による売上、不足額、必要時間、必要平均単価を表示します。件数指定方式では売上不足を埋める件数を自動追加しません。自動補完が必要な場合はクエスト優先方式を選びます。

旧比率はデータ互換のため保存データ内に保持します。既存設定は会社別件数を入力するまで従来計算を維持し、画面にはその旨を表示します。新しい計画件数は同じJSONバックアップに保存されます。

## 前半・後半の売上目標

週タブでは前半（月〜木）・後半（金〜日）の目標を入力し、週全体はその合計を読み取り専用で表示します。前半30,000円・後半50,000円なら週80,000円です。各期間の実績、不足額、日別配分、クエスト報酬、会社別必要件数・時間を期間ごとに計算します。期間をまたいだ未達・超過の自動移動は行いません。終わった期間の不足額は未配分として表示します。

既存の週目標は変更せずに読み込みます。前半・後半の入力欄には4日・3日の仮内訳を表示し、いずれかを編集すると期間別計画へ切り替えます。期間目標は既存の週目標オブジェクトへ `front` / `back` として追加し、従来の `amt` にも合計を保存します。件数目標など既存フィールドは保持します。JSONバックアップ・復元でも引き継ぎます。

会社別件数の直接入力は引き続き週合計です。入力件数は週の稼働日数に応じて前半・後半に割り当て、各期間の実績件数を控除します。Uberクエストの必要件数は最低限確保します。標準の月〜木・金〜日のクエスト報酬を対応する期間に反映し、期間をまたぐ既存クエストは終了日の属する期間に一度だけ割り当てます。
