# デリログ：売上シミュレーション

「目標管理」「逆算」を「🧮 売上シミュレーション」に統合。週・月・年の3タブで目標を設定します。ホームの日・週・月・年の集計切り替えと、日々の実績入力は継続します。

## 週とホーム

- 週は月〜日、日本時間04:00を営業日の境界とします。
- 週目標から入力済み実績を差し引き、過去の日と休みを除いた稼働日に配分します。
- 日別の指定額はその日の総額です。指定額と実績の高い方を確保し、残りを自動配分日に均等配分します。1円単位の余りは日付順に配分します。
- 例：残り3日・30,000円なら10,000円ずつ。今日を8,000円に指定すると、残りは11,000円ずつ。
- 当日実績が自動配分額に達するまでは当日の目標総額を維持し、残り必要額・件数・時間が減少します。超過分はほかの日の必要額を減らします。
- 配分する日がない不足額、指定額による過剰配分は明示します。
- ホームは今日の週配分を表示します。ホームから配分を直接編集せず、売上シミュレーションの週タブへ移動します。
- 必要件数は通常単価・会社比率による売上条件と、Uberクエストの本日ノルマを満たす件数です。必要時間は追加件数÷UPH。単価やUPHがない場合は未設定と表示します。

## Uber Eatsクエスト

- 前半は月〜木、後半は金〜日。Uber Eatsの入力済み件数だけを集計し、対象外件数を控除します。他社の件数は加算しません。
- 基本達成と追加10回の報酬を別に設定します。「達成を確認」しても実績売上を自動作成しません。
- 入力済みの確定報酬と、未入力の報酬見込みを分けて表示します。実績集計には、ホームに入力した売上・報酬だけを含めます。
- クエスト期間内に入力済みのUber報酬は見込みから自動控除します。別日に入力済みの報酬は明示的に紐付けます。各報酬は一度だけ控除し、入力済み金額を超える紐付けは保存しません。
- 同期間の別種のUber報酬も自動控除の対象になるため、見込みは保守的な値になります。実績売上はそのまま保持します。
- 未確認のまま終了したクエストは見込みから外れます。結果を確認した未入力報酬は、実績に入力するまで見込みとして区別します。
- 「クエスト見込みを週の必要売上から差し引く」は週ごとの任意設定で、初期状態はオフです。見込みが実績に混ざることはありません。

## 月・年

- 対象期間内に入力した全プラットフォームの通常売上・報酬を、日ごとの最終累計値から一度ずつ集計します。
- それぞれの目標・残り想定稼働日数・今後1日あたりの追加売上から、必要売上と着地を計算します。残り日数には今日を含みます。
- 今後1日の売上想定が空欄の場合は、対象期間内で今日までに売上を入力した日の平均を使います。今日の追加想定は、既に入力した売上に上乗せする金額です。
- 週・月・年の目標と想定は独立しています。月や年の変更で週目標・日別配分を上書きせず、週からも月・年を上書きしません。
- 月・年の計算にはクエストの未入力見込みを含めず、試算から実績への書き込みも行いません。

## データ互換性

既存の保存キーを継続します。

| データ | localStorageキー |
| --- | --- |
| 売上実績 | `delivery_log_vault_v13` |
| 期間別目標 | `delivery_log_periodic_goals_v13` |
| 稼働予定・クエスト・試算設定 | `delivery_log_planning_v15` |
| メモ | `delivery_log_inbox_memos_v13` |
| 経費 | `delivery_log_expenses_v1` |

既存の週・月・年の目標キー、件数目標、クエスト、日別指定、プリセットを保持します。以前の日目標は日別指定として読み込み、「自動配分」への明示的な切り替えで解除できます。廃止した比較画面の設定値も保存データから削除しません。

新しい `weekly`（週ごとの見込み反映）と `horizons`（月・年ごとの想定）は任意フィールドです。旧v15の計画は書き換えずに読み込めます。JSONバックアップはv16で出力し、v13・v14・v15・v16および従来の実績単体形式を読み込めます。旧バックアップにない計画・経費は現在の値を保持します。

計画データの読み込みに失敗した場合は、元の値を上書きせず保存を停止します。設定画面で有効なJSONバックアップから復元できます。
